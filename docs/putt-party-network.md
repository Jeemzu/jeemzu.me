# Better Putt Party networking

The `games-realtime` service in the `games-api` repo (`src/GamesRealtime`) owns rooms, shots, and scoring. Clients replay each shot locally with the same deterministic physics, so rolling balls are never streamed.

## Endpoint

- `VITE_GAMES_REALTIME_URL` + `/v1/games/putt-party/ws`.
  - Development: `ws://localhost:5290` (`dotnet run --project src/GamesRealtime` in `games-api`).
  - Production: `wss://play.jeemzu.me`.
- The browser `Origin` must be listed in the service's `Realtime:AllowedOrigins`.
- Messages are JSON with a `type` field. The shapes are in `src/games/puttparty/net/protocol.ts`, mirrored by `Putt/PuttProtocol.cs`.

## Messages

- Client → server: `create`, `join`, `resume`, `selectCourse`, `start`, `shot`, `returnToLobby`, `leave`, `ping`.
- Server → client: `welcome`, `course`, `state`, `shotStarted`, `pong`, `error`.

## Sync rules

- The server checks each shot, then broadcasts `shotStarted` to the whole room with the exact launch (`x`, `z`, `vx`, `vz`), `strokes`, and `elapsed` (seconds already simulated; non-zero only when replayed to a resuming player).
- The shooter predicts locally on release.
  - If the echoed launch matches exactly, the prediction is kept.
  - Otherwise it is relaunched and fast-forwarded by the elapsed time.
  - With no echo within 3 s, or on an `error`, the prediction is cancelled.
- The server still simulates at 120 Hz. It sends `state` only when something changes (a join, a shot, a ball stopping, scoring), plus a 1 s heartbeat. `state` positions are unrounded.
- Physics in `physics.ts` must stay bit-identical to `PuttPhysics.cs`.
  - Use `Math.sqrt(dx * dx + dz * dz)`; never `Math.hypot`.
  - Balls never collide with each other, so each shot depends only on its launch and the hole.
- Reconciliation (`sim.ts`):
  - A local roll is kept until `state` includes that stroke.
  - Once it does, the ball eases to the server's resting position.
  - A local roll still moving 1.5 s after the server reports the ball at rest is stopped.
  - Aiming waits until the local ball has settled.

## Ping

- The client sends `ping { t }` every 2 s. The server answers `pong { t }` directly, outside the tick loop.
- The top-right chip shows the latest round trip. Its tooltip shows the min, average, and jitter of the last 10 samples, and the most recent shot-confirmation time.

## Physics parity fixture

- `physics.fixture.json` is generated by the server and checked by both `physics.test.ts` and `PuttPhysicsFixtureTests`.
- After changing physics constants, collision code, or the built-in course:
  1. In `games-api`, run `$env:PUTT_FIXTURE_UPDATE=1; dotnet test tests/GamesRealtime.Tests --filter PuttPhysicsFixtureTests`.
  2. Copy `tests/GamesRealtime.Tests/Fixtures/putt-physics.json` to `src/games/puttparty/physics.fixture.json`.
  3. Run `npx vitest run src/games/puttparty`.
